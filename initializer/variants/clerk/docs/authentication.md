# Clerk authentication

This project was generated with Clerk rather than Better Auth. Set up a separate Clerk application for this project. Enable email/password, require email verification, and configure the sign-in URL `/login`, sign-up URL `/signup`, and your production origins. Set `NEXT_PUBLIC_CLERK_PUBLISHABLE_KEY` and `CLERK_SECRET_KEY` in `.env.local` and production hosting. Rebuild after changing the public key. No Clerk account or instance is created automatically.

Clerk's prebuilt sign-in and sign-up components handle verification and password recovery. `/account` provides Clerk's security settings; the dashboard's display name and onboarding remain local application data. Logout uses Clerk's sign-out component. Clerk sends authentication emails; this variant does not install Resend or Better Auth.

Every protected page and API handler resolves the signed-in Clerk user on the server, checks its ID against the session, and requires a verified primary email. It synchronizes the local user by Clerk ID, never by email. Conflicting email addresses fail closed rather than linking accounts. A provider outage fails closed. The fresh provider read avoids granting access from stale email claims. Account deletion in Clerk revokes access; local notes and billing records remain until an explicit retention/deletion process handles them. Existing Stripe subscriptions are not silently canceled by deleting an identity.

Both database options keep the same Postgres schema and migration history. Better Auth's session/account/verification/rate-limit tables are dormant in this variant; no Clerk session or password is stored in them. Keep them when applying shared database fixes; remove them with an explicit migration if desired. This initializer creates new projects; changing a flag is not an existing-user migration between providers.

`npm run check` runs types, unit tests and builds without credentials. `npm run test:database` uses local Postgres fixtures for verified identity mapping, repeat synchronization, email collision refusal, ownership, invalid input and RLS. The SDK login, verification, reset and logout flows still need testing against your configured Clerk development instance. The Better Auth browser fixture is omitted because it cannot exercise Clerk's hosted identity service. Stripe policy tests remain; use a Stripe sandbox to verify Checkout and webhook delivery. No mock identity bypass ships in application code.
