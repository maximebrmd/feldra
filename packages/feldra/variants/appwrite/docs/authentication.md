# Appwrite authentication

This project was generated with Appwrite Auth rather than Better Auth. Create a separate Appwrite project for this SaaS. Enable email/password, require email verification, and add an API key with the Sessions write scope. Set `NEXT_PUBLIC_APPWRITE_ENDPOINT`, `NEXT_PUBLIC_APPWRITE_PROJECT_ID`, and `APPWRITE_API_KEY` in `.env.local` and production hosting. Rebuild after changing the public endpoint or project ID. No Appwrite account or project is created automatically.

Appwrite delivers verification and password-recovery emails from the console (SMTP or Appwrite Cloud). This variant does not install Resend or Better Auth. Signup, login, verification, password reset and logout run through Next.js route handlers using `node-appwrite` 29. The session secret is stored in an httpOnly `appwrite-session` cookie. The browser never receives the secret and does not talk to Appwrite directly. Password reset revokes existing Appwrite sessions and clears the local cookie.

Every protected page and API handler resolves the signed-in Appwrite account on the server, checks its ID against the session, and requires a verified email. It synchronizes the local user by Appwrite ID, never by email. Conflicting email addresses fail closed rather than linking accounts. A provider outage fails closed. The fresh provider read avoids granting access from stale email claims. Account deletion in Appwrite revokes access; local notes and billing records remain until an explicit retention/deletion process handles them. Existing Stripe subscriptions are not silently canceled by deleting an identity. Server-side resource authorization remains mandatory; the Appwrite session is request context only.

Both database options keep the same Postgres schema and migration history. Better Auth's session/account/verification tables are dormant in this variant; no Appwrite session or password is stored in them. Login, signup, password recovery and verification-resend routes write per-IP limits to the shared `rate_limit` table because the API key bypasses Appwrite's client IP limits. Keep the unused Better Auth tables when applying shared database fixes; remove them with an explicit migration if desired. This initializer creates new projects; changing a flag is not an existing-user migration between providers. Neon or Supabase still supply Postgres; Appwrite is not used as a database in this variant.

`npm run check` runs types, unit tests and builds without credentials. `npm run test:database` uses local Postgres fixtures for verified identity mapping, repeat synchronization, email collision refusal, ownership, invalid input and RLS. The SDK login, verification, reset and logout flows still need testing against your configured Appwrite development project. The Better Auth browser fixture is omitted because it cannot exercise Appwrite's hosted identity service. Stripe policy tests remain; use a Stripe sandbox to verify Checkout and webhook delivery. No mock identity bypass ships in application code.
