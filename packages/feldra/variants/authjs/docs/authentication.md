# Auth.js authentication

This project was generated with Auth.js (NextAuth) rather than Better Auth. Create a separate GitHub OAuth app for this project. Set the homepage URL to `APP_URL` and the authorization callback URL to `APP_URL/api/auth/callback/github`. Set `AUTH_GITHUB_ID` and `AUTH_GITHUB_SECRET` in `.env.local` and production hosting. The initializer writes a local `AUTH_SECRET`; generate a distinct production value. Rebuild after changing keys. No GitHub OAuth app is created automatically.

Auth.js has no separate sign-up flow. `/login` and `/signup` both start GitHub OAuth; the first successful callback creates the local user. GitHub must provide a verified primary email. Password reset and email verification stay on GitHub; `/forgot-password`, `/reset-password` and `/verify-email` redirect to login. Logout uses Auth.js `signOut`. This variant does not install Resend or Better Auth. Add further Auth.js providers in `packages/auth/auth.ts` if needed.

Every protected page and API handler resolves the signed-in Auth.js session on the server and requires a GitHub user id plus email. It synchronizes the local user by GitHub id (`github:{id}`), never by email. Conflicting email addresses fail closed rather than linking accounts. A provider outage fails closed. Session cookies are request context only; notes, billing and other private queries authorize with the persisted local user id. Account deletion on GitHub revokes new sign-ins; local notes and billing records remain until an explicit retention/deletion process handles them. Existing Stripe subscriptions are not silently canceled by deleting an identity.

Both database options keep the same Postgres schema and migration history. Better Auth's session/account/verification/rate-limit tables are dormant in this variant; Auth.js uses a signed JWT session rather than those tables. Keep them when applying shared database fixes; remove them with an explicit migration if desired. This initializer creates new projects; changing a flag is not an existing-user migration between providers.

`npm run check` runs types, unit tests and builds without GitHub credentials. `npm run test:database` uses local Postgres fixtures for verified identity mapping, repeat synchronization, email collision refusal, ownership, invalid input and RLS. The GitHub OAuth login, callback and logout flows still need testing against your configured OAuth app. The Better Auth browser fixture is omitted because it cannot exercise GitHub's hosted identity service. Stripe policy tests remain; use a Stripe sandbox to verify Checkout and webhook delivery. No mock identity bypass ships in application code.
