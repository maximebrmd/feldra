## サンプルリソース [#the-example-resource]

非公開ノートは、作成、読み取り、更新、削除の一連の動作を示します。サーバー上では、入力の検証に厳格な Zod スキーマを使用します。未知のフィールドや無効な値は拒否されます。

すべてのクエリは、認証済みユーザーのデータのみを対象とします。更新と削除では、SQL の条件にノート ID と所有者 ID を含めます。他のユーザーのレコードと存在しないレコードには、同じ「見つかりません」という応答を返します。

## データベースの保護 [#database-protection]

すべての基本テーブルで、クライアント向けポリシーを設定せずに行レベルセキュリティを有効にしています。所有者ではなく、BYPASSRLS も持たないロールによる直接アクセスは拒否されます。これは、Supabase の public スキーマと Data API を使用する際に重要です。

アプリケーションはデータベースの所有者として接続するため、サーバー側での所有権チェックは引き続き必須です。使用していない Supabase Data API を無効にし、すべての接続文字列を非公開にしてください。

## サンプルの削除 [#remove-the-example]

ノートの UI、`apps/app/src/lib/notes.ts`、`apps/app/src/app/api/notes` を削除してください。ダッシュボードのビューと設定内の有料エクスポートリンクを、ご自身のプロダクトの機能に置き換えてください。

`packages/database/src/schema.ts` から `note` テーブルを削除し、新しいマイグレーションを生成して内容を確認してください。

```sh
npm run db:generate
npm run db:migrate
```

既存のプロジェクトに適用済みのマイグレーションを書き換えないでください。削除用のマイグレーションを適用する前に、失われるデータを確認してください。所有権のテストは残し、実際のリソースに合わせて拡張してください。
