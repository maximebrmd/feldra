## ローカル環境 [#local-environment]

初期化ツールは `.env.example` から `.env.local` を作成し、新しい Better Auth シークレットを生成します。プロバイダーの項目は空欄のままです。これらの項目は使用時に検証されるため、設定が不足している場合は明示的なエラーになります。

| 変数 | 設定内容 |
| --- | --- |
| `WEB_URL` | マーケティングサイトのオリジンです。ローカルでは `http://localhost:3000` を使用します |
| `APP_URL` | アプリケーションのオリジンです。ローカルでは `http://localhost:3001` を使用します |
| `BETTER_AUTH_SECRET` | 生成されたローカル用シークレットです。本番環境では別のシークレットを使用します |
| `DATABASE_URL` | プロバイダーが提供するプール型の Postgres 接続です |
| `DATABASE_URL_UNPOOLED` | マイグレーション用の直接接続、または IPv4 での Supabase セッションプーラーです |
| `RESEND_API_KEY` | ご自身の Resend アカウントのキーです |
| `EMAIL_FROM` | 検証済みの送信ドメインに属するメールアドレスです |
| `STRIPE_SECRET_KEY` | 開発中は Stripe サンドボックスのシークレットキーを使用します |
| `STRIPE_WEBHOOK_SECRET` | 実際のリスナーまたはエンドポイントの署名用シークレットです |
| `STRIPE_PRO_PRICE_ID` | ご自身のプランに対応する継続課金の料金です |
| `STRIPE_LIVE_MODE` | サンドボックスでは `false` にします。対応する本番用リソースを使用する場合にのみ `true` にします |

## データベースの設定 [#database-setup]

接続モード、TLS、Supabase Data API の制限については、[データベースの選択](/docs/databases/)に従ってください。SaaS ごとに独立したプロバイダーリソースを使用し、開発環境と本番環境を分離してください。

## トランザクションメール [#transactional-email]

Resend で送信者ドメインを検証してください。`RESEND_API_KEY` と `EMAIL_FROM` を入力し、アプリケーションの公開オリジンを使用して、新規登録時の確認メールとパスワードリセットメールをテストしてください。

## サブスクリプションの設定 [#subscription-setup]

Stripe でサンドボックス用の商品と継続課金の料金を作成し、カスタマーポータルを有効にして、Webhook エンドポイントを設定してください。必要なイベントと制限付きキーの権限の詳細については、[サブスクリプションと請求](/docs/billing/)および生成された `docs/setup.md` に従ってください。

## シークレットの保護 [#keep-secrets-private]

`.env.local` をコミットしたり、公開環境変数にデータベースの認証情報を入れたり、派生プロジェクトのシークレットを別の SaaS で再利用したりしないでください。プレビューデプロイを本番データに接続してはいけません。プロバイダーの認証情報が必要なのは、認証機能を備えたアプリだけです。
