初期化ツールでは、矢印キーと Enter キーで Neon または Supabase を選択できます。非対話型のコマンドでは、`--yes --database neon` または `--yes --database supabase` を使用します。デフォルトは Neon です。選択したデータベースは、`template-origin.json`、`.env.example`、`DATABASE.md` に記録されます。

どちらを選んでも、同じ Drizzle スキーマ、マイグレーション、node-postgres ドライバー、Better Auth Drizzle アダプターを使用します。これらは標準の Postgres 接続であり、Supabase SDK、Supabase Auth、匿名キー、サービスロール API キーは不要です。データベースの選択によって変わるのはセットアップ手順であり、アプリケーションの API は変わりません。初期化ツールによるリソースのプロビジョニングは行われません。

## Neon

SaaS ごとに独立した Neon プロジェクトを作成します。プール接続 URL を `DATABASE_URL` に、直接接続 URL を `DATABASE_URL_UNPOOLED` にコピーします。Neon が提供する接続セキュリティパラメーターはそのまま保持してください。開発用と本番用で別々のブランチやデータベースを設定します。

## Supabase

SaaS ごとに独立した Supabase プロジェクトを作成します。ダッシュボードの **接続** パネルで、**トランザクションプーラー**の接続文字列（ポート 6543）を `DATABASE_URL` にコピーします。`DATABASE_URL_UNPOOLED`（マイグレーション用）には**直接接続**を使用します。IPv4 のみのネットワークでは、代わりに**セッションプーラー**（ポート 5432）を使用します。ダッシュボードからホストとユーザー名を正確にコピーし、URL エンコードしたデータベースパスワードを挿入して、必要な TLS 設定を保持してください。接続エラーを回避するために証明書の検証を無効にしないでください。[Supabase の接続オプション](https://supabase.com/docs/guides/database/connecting-to-postgres)を参照してください。

サーバーとマイグレーションには、プロジェクトが提供するデータベース所有者の認証情報を使用します。トランザクションプーラーは名前付きプリペアドステートメントをサポートしていません。このテンプレートでは、それらを作成しません。接続モードを見直さずに `.prepare()` クエリを追加しないでください。サーバーの接続プールはプロセスごとに 1 つの接続を使用します。デプロイ時の同時実行数も、プロバイダーの接続数制限に収まるようにする必要があります。

Supabase のプロジェクト設定で、使用しない **データ API** を無効にします。このテンプレートは、認証済みの Next.js ルートハンドラーを通じてのみデータを提供します。マイグレーションでは、クライアント向けのポリシーを設定せずに、全 9 テーブルで行レベルセキュリティを有効にします。これにより、テーブルへの権限が付与されていても、所有者ではなく BYPASSRLS 権限も持たないロールからの読み取りと書き込みが拒否されます。認証トークン、パスワードハッシュ、課金状態、非公開のメモを、クライアントからの直接アクセスから保護します。サーバークエリはテーブル所有者として実行されるため、RLS をバイパスします。サーバーでのユーザー所有権の確認は引き続き必須です。Supabase のサービスロール API によるアクセスも RLS をバイパスするため、そのキーは非公開にしてください。データベース URL をブラウザーに公開しないでください。[Supabase API のセキュリティ](https://supabase.com/docs/guides/api/securing-your-api)と [RLS](https://supabase.com/docs/guides/database/postgres/row-level-security) を参照してください。

新しく追加するテーブルでも RLS を有効にしてください。後でデータ API を有効にする場合は、公開するスキーマ、テーブルへの権限付与、ポリシーを明示的に確認してください。Better Auth のセッションは Supabase JWT ではありません。Supabase Auth との連携は含まれていません。

## セットアップを完了する [#finish-setup]

[セットアップ](/docs/environment/)の説明に従って Resend と Stripe の値を入力し、生成されたプロジェクトのルートから次のコマンドを実行します。

```sh
npm run db:migrate
npm run check
npm run dev
```

`.env.local` は非公開にしてください。プロジェクトおよび環境ごとに異なる認証情報とプロバイダーのリソースを使用します。新しいデータベースへのトラフィックを許可する前に、マイグレーションを実行する必要があります。テストフィクスチャでは使い捨てのローカル Postgres を使用します。実際の Neon/Supabase への接続にはご自身の認証情報が必要であり、フィクスチャテストでは検証されません。
