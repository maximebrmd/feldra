## リリース状況 [#release-status]

Feldra は、このプロジェクトの新しいブランドです。初期化パッケージは `feldra` で、npm にはまだ公開されていません。明示的な公開リリースがあるまで、ローカルのバージョンは **0.1.0** のままです。公開後は `npx feldra create` を実行します。メンテナーは Changesets を通じてバージョンを管理しています。未公開のあいだは、0.1.0 を超えるバージョン PR をマージしないでください。

## リリースワークフロー [#release-workflow]

```sh
npm run changeset
npm run changeset:status
npm run release:version
```

バージョン更新コマンドは、保留中の変更メモを処理し、`packages/feldra/CHANGELOG.md` を生成し、初期化ツールとルートのバージョンを更新し、ロックファイルを更新します。公開は行いません。0.1.0 の npm 公開が承認されるまで、保留中の Changesets は消費しないでください。明示的な承認を得て npm に公開する前に、パッケージ化した成果物をテストしてください。[リポジトリのリリースガイド](https://github.com/maximebrmd/feldra/blob/main/docs/releasing.md) を参照してください。

## ローカルでのリリース履歴 [#local-release-history]

### 0.1.0 — 最初の公開リリース（まだ公開されていません） [#010-\-first-public-release-not-published-yet]

ツリー内で以前 0.2.0/0.3.0 と番号付けされ、npm には公開されなかったローカル開発履歴と、保留中の Changeset メモです。

- **破壊的変更:** 公開パッケージと CLI の名前を `create-feldra` から `feldra` に変更します。`npm create feldra` の代わりに `npx feldra create` を実行してください。引数なしの `npx feldra` は `create` を含むヘルプを表示します。
- テンプレート名を Feldra に変更します。生成されるプロジェクトのブランディング、CLI コマンド、リリースメタデータ、テスト、ドキュメントを更新します。npm への公開は別のリリース手順のままです。
- 初期化パッケージを `initializer/` から `packages/feldra` へ移します。
- Changesets と生成される changelog で初期化ツールのリリースを管理します。リリース用ツールは生成される SaaS プロジェクトの外に置き、リリースバージョンを同梱テンプレートと同期します。
- 生成されるプロジェクトには、ソースリポジトリの README ではなくプロダクト README を同梱します。
- 独立した Feldra の Astro ドキュメントサイトを追加し、そのアプリとツールを生成される SaaS プロジェクトから除外します。Astro の型チェックと互換性のある共有 TypeScript バージョンを使用します。
- Neon または Supabase に加えて、Better Auth または Clerk を独立して選択できるようにします。Clerk のコードと解決済みの依存関係ロックファイルを同梱し、Clerk プロジェクトから未使用の Better Auth/Resend ツールを削除し、サーバー側の認可を維持し、マネージド認証のセットアップとライブ検証の制限を文書化します。
- 矢印キーによる対話形式の Neon/Supabase データベース選択と、CI 向けの `--database` を追加します。
- プロバイダー別のセットアップ手順、環境設定のコメント、生成元のメタデータを生成します。
- すべてのプライベートテーブルで RLS を有効にします。サーバー側の所有権チェックと、共通の Postgres/Drizzle アクセスは維持します。
- パッケージ化した npm リリースを使って、両方のデータベース選択肢をテストします。
- マーケティング用と認証付きの Next アプリを分離し、ソースをエクスポートする 6 つの共有パッケージと Turborepo を備えた、next-forge 形式の npm モノレポを生成します。
- ターミナルでのセットアップ・確認プロンプトと `--preset neon` を追加し、`--yes` および非 TTY 環境での自動化を維持します。未実装のプロバイダーは選択肢に含めません。
- 実装済みの Neon/Better Auth/Stripe/Resend ツールキットを維持し、データベースマイグレーションは変更しません。
- 両方の本番用アプリ、アプリ間のナビゲーション、ワークスペースのタスクグラフ、実際にパッケージ化した配布物をテストします。生成済みの既存プロジェクトは自動的には変更されません。
- 単一アプリ構成の初期 SaaS 基盤と、同梱の npm 初期化ツールです。後に上記のモノレポアーキテクチャへ置き換えられました。
