## SaaSアプリをデプロイします [#deploy-the-saas-apps]

Next.jsのホスティングサービス上で、同じ生成済みリポジトリに接続する2つのプロジェクトを作成します。

| プロジェクト | ルートディレクトリ | 用途 |
| --- | --- | --- |
| マーケティング | `apps/web` | ランディングページと料金ページ |
| アプリケーション | `apps/app` | 認証、ダッシュボード、API、Webhook |

ルートのnpmロックファイルを使用して、すべてのワークスペースの依存関係をインストールします。Next.jsが共有パッケージをコンパイルできるように、各プロジェクトのルート外にあるソースファイルへのアクセスを有効にします。プラットフォームのNext.jsプリセットを使用します。

## 本番環境のオリジンを設定します [#set-production-origins]

両方のデプロイで、`WEB_URL`と`APP_URL`にそれぞれの正確なHTTPSオリジンを設定します。データベース、認証、Stripe、Resendの認証情報は、アプリケーションのデプロイにのみ設定します。

本番環境用に新しく生成した認証シークレット、本番データベース、検証済みの送信者、および互いに整合するStripeの本番用キー、価格、エンドポイントシークレット、モードを使用します。認証Cookieはアプリケーションのオリジンに属します。

## マイグレーションを適用します [#apply-migrations]

アプリケーションのトラフィックを対象のデータベースに向ける前に、そのデータベースに対して`npm run db:migrate`を実行します。各マイグレーションを確認し、重要なデータを削除または変換する可能性のある変更を加える前に、そのデータをバックアップします。

## 公開前に検証します [#verify-before-launch]

実際にホストされているアプリケーションで、確認リンク、パスワードのリセット、セッションの失効、非公開レコードへのアクセス認可、Checkout、ポータルでの変更、Webhookの配信をテストします。テンプレートのローカルテスト用フィクスチャでは、本番環境の設定は検証されません。

## このドキュメントサイトについて [#this-documentation-site]

Feldraのドキュメントは、独立した静的Astroアプリです。テンプレートリポジトリのルートで、次のコマンドを実行します。

```sh
npm run build --workspace docs
npm run preview --workspace docs
```

出力先は`apps/docs/dist`です。ディレクトリインデックスのルーティングと生成された`404.html`に対応する静的ホスティングサービスで配信できます。サーバーアダプターやプロバイダーの認証情報は不要です。ドキュメントアプリは、生成されるSaaSプロジェクトには含まれません。自動的にデプロイされるものはありません。
