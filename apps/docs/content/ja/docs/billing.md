## Stripe サンドボックスから始めます [#start-with-a-stripe-sandbox]

Pro 商品と、`packages/config/index.ts` に一致する月額の継続課金価格を作成します。`STRIPE_SECRET_KEY`、`STRIPE_PRO_PRICE_ID`、`STRIPE_LIVE_MODE=false` を設定します。カスタマーポータルを有効にします。

各ユーザーは、1 つの請求行と、サーバーが作成した Stripe 顧客との対応付けを所有します。サーバーは、送信された顧客 ID を所有権の証明として受け入れることはありません。

## チェックアウトとポータル [#checkout-and-portal]

チェックアウトルートは、請求行単位で処理を直列化し、安定した冪等性キーを使用し、開いているセッションを再利用します。また、まだ終了していないサブスクリプションがある場合は、2 つ目のサブスクリプションを拒否します。サブスクリプションの管理はカスタマーポータルで行います。

## 署名付きで再試行可能な Webhook [#signed-retryable-webhooks]

Webhook エンドポイントは、アプリケーションのオリジン上にあります。

```text
/api/webhooks/stripe
```

このエンドポイントは、生のリクエスト本文、Stripe の署名、タイムスタンプの許容範囲、サンドボックス／本番モードを検証します。サポート対象のイベントでは、請求行をロックし、一意の受信記録を挿入し、Stripe の現在のサブスクリプション状態を取得して、トランザクション内でスナップショットを永続化します。

イベント ID が重複している場合は、何も行いません。失敗した場合は受信記録と状態をロールバックし、再試行が成功できるようにします。順序が前後したイベントでは、イベントのタイムスタンプを信用するのではなく、プロバイダーの現在の状態と整合させます。

## 有料機能へのアクセスを制御します [#enforce-paid-access]

サンプルの `/api/notes/export` エンドポイントは、Pro 専用の操作です。サーバー側でアクセス権を確認する前に、Stripe の状態と整合させます。チェックアウト成功時の URL にアクセスしても、アクセス権は付与されません。

プロバイダーで障害が発生した場合、有料操作はサービス利用不可のレスポンスを返して失敗します。無料のノート機能は引き続き利用できます。サーバー側のチェックを維持しながら、サンプルのエクスポート処理を実際の有料機能に置き換えてください。

## ローカル環境への Webhook 転送 [#local-webhook-forwarding]

生成された `docs/setup.md` に記載されているイベント一覧と Stripe CLI コマンドを、そのまま使用してください。イベントを `localhost:3001/api/webhooks/stripe` に転送し、リスナーの署名シークレットを `STRIPE_WEBHOOK_SECRET` にコピーします。

本番環境のホスト型 Checkout、ポータル、受信トレイへの配信、プロバイダーから送信される Webhook を利用するには、ご自身の認証情報と検証が必要です。
