## स्थानीय परिवेश [#local-environment]

इनिशियलाइज़र `.env.example` से `.env.local` बनाता है और Better Auth के लिए एक नया सीक्रेट जनरेट करता है। प्रदाता के फ़ील्ड खाली रहते हैं। उपयोग के समय उनका सत्यापन किया जाता है, इसलिए कॉन्फ़िगरेशन अनुपस्थित होने पर स्पष्ट त्रुटि मिलती है।

| वेरिएबल | क्या कॉन्फ़िगर करें |
| --- | --- |
| `WEB_URL` | मार्केटिंग साइट का ओरिजिन; स्थानीय रूप से `http://localhost:3000` |
| `APP_URL` | एप्लिकेशन का ओरिजिन; स्थानीय रूप से `http://localhost:3001` |
| `BETTER_AUTH_SECRET` | जनरेट किया गया स्थानीय सीक्रेट; प्रोडक्शन के लिए अलग सीक्रेट उपयोग करें |
| `DATABASE_URL` | आपके प्रदाता से प्राप्त पूल किया गया Postgres कनेक्शन |
| `DATABASE_URL_UNPOOLED` | माइग्रेशन के लिए सीधा कनेक्शन, या IPv4 पर Supabase सेशन पूलर |
| `RESEND_API_KEY` | आपके अपने Resend खाते की कुंजी |
| `EMAIL_FROM` | आपके सत्यापित प्रेषण डोमेन का एक ईमेल पता |
| `STRIPE_SECRET_KEY` | डेवलपमेंट के दौरान Stripe सैंडबॉक्स की सीक्रेट कुंजी |
| `STRIPE_WEBHOOK_SECRET` | वास्तविक लिसनर या एंडपॉइंट के लिए साइनिंग सीक्रेट |
| `STRIPE_PRO_PRICE_ID` | आपकी योजना के अनुरूप आवर्ती मूल्य |
| `STRIPE_LIVE_MODE` | सैंडबॉक्स के लिए `false`; केवल अनुरूप लाइव संसाधनों के साथ `true` |

## डेटाबेस सेटअप [#database-setup]

कनेक्शन मोड, TLS और Supabase Data API के प्रतिबंधों के लिए [अपना डेटाबेस चुनें](/docs/databases/) का पालन करें। प्रत्येक SaaS के लिए स्वतंत्र प्रदाता संसाधनों का उपयोग करें और डेवलपमेंट को प्रोडक्शन से अलग रखें।

## लेन-देन संबंधी ईमेल [#transactional-email]

Resend में एक प्रेषक डोमेन सत्यापित करें। `RESEND_API_KEY` और `EMAIL_FROM` भरें, फिर अपने एप्लिकेशन के सार्वजनिक ओरिजिन का उपयोग करके साइनअप सत्यापन ईमेल और पासवर्ड रीसेट ईमेल का परीक्षण करें।

## सदस्यता सेटअप [#subscription-setup]

Stripe में एक सैंडबॉक्स उत्पाद और आवर्ती मूल्य बनाएँ, ग्राहक पोर्टल सक्षम करें और अपना वेबहुक एंडपॉइंट कॉन्फ़िगर करें। सटीक इवेंट और प्रतिबंधित कुंजी की अनुमतियों के लिए [सदस्यताएँ और बिलिंग](/docs/billing/) तथा जनरेट की गई `docs/setup.md` का पालन करें।

## सीक्रेट गोपनीय रखें [#keep-secrets-private]

कभी भी `.env.local` कमिट न करें, डेटाबेस क्रेडेंशियल सार्वजनिक परिवेश वेरिएबल में न रखें और किसी व्युत्पन्न परियोजना के सीक्रेट का किसी अन्य SaaS के लिए दोबारा उपयोग न करें। प्रीव्यू डिप्लॉयमेंट को प्रोडक्शन डेटा से कनेक्ट नहीं करना चाहिए। केवल प्रमाणीकरण वाले ऐप को प्रदाता क्रेडेंशियल की आवश्यकता होती है।
