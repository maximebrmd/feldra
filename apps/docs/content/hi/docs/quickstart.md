## पूर्वापेक्षाएँ [#prerequisites]

Node.js 24 LTS, npm और Git का उपयोग करें। Docker की आवश्यकता केवल स्थानीय डेटाबेस और ब्राउज़र फ़िक्स्चर के लिए है। टेम्पलेट बिल्ड करने या उन फ़िक्स्चर को चलाने के लिए आपको प्रदाता के क्रेडेंशियल की आवश्यकता नहीं है।

## सोर्स प्राप्त करें [#get-the-source]

```sh
git clone https://github.com/maximebrmd/feldra.git feldra
cd feldra
npm ci
```

## अपना प्रोजेक्ट बनाएँ [#create-your-project]

इनिशियलाइज़र अभी npm पर प्रकाशित नहीं किया गया है। पहले संस्करणयुक्त स्थानीय पैकेज बिल्ड करें:

```sh
npm run initializer:pack
```

यह सोर्स को सत्यापित करता है और रिपॉज़िटरी के मूल फ़ोल्डर में `create-feldra-VERSION.tgz` लिखता है। नीचे VERSION को `initializer/package.json` में दिए गए संस्करण से बदलें:

```sh
npm exec --yes --package="./create-feldra-VERSION.tgz" -- create-feldra my-new-saas
```

**Neon** या **Supabase** चुनने के लिए तीर कुंजियों और Enter का उपयोग करें। इनिशियलाइज़र डिपेंडेंसी इंस्टॉल करता है, स्थानीय एनवायरनमेंट फ़ाइलें लिखता है और एक नई Git रिपॉज़िटरी आरंभ करता है। यह पहले से मौजूद गंतव्य को स्वीकार नहीं करता, भले ही वह खाली हो।

बिना इंटरैक्शन के चलाने के लिए, प्रोजेक्ट के नाम के बाद `--yes --database supabase` जोड़ें। सापेक्ष पथ और उद्धरण चिह्नों में लिखे गए स्पेस वाले पथ, दोनों काम करते हैं।

## अपने प्रदाताओं से कनेक्ट करें [#connect-your-providers]

```sh
cd my-new-saas
```

जनरेट की गई `DATABASE.md` और [एनवायरनमेंट गाइड](/docs/environment/) का उपयोग करके `.env.local` भरें। एक नया स्थानीय Better Auth सीक्रेट पहले ही जनरेट किया जा चुका है; डेटाबेस, ईमेल और भुगतान के क्रेडेंशियल अलग से कॉन्फ़िगर करने होंगे।

```sh
npm run db:migrate
npm run check
npm run dev
```

मार्केटिंग के लिए **localhost:3000** और प्रमाणीकरण वाले एप्लिकेशन के लिए **localhost:3001** खोलें।

## npm पर प्रकाशन के बाद [#after-npm-publication]

वर्तमान पैकेज प्रकाशित होने के बाद, प्रोजेक्ट बनाने का कमांड यह होगा:

```sh
npm create feldra@latest my-new-saas
```

जब तक पैकेज स्पष्ट रूप से प्रकाशित न कर दिया जाए, सार्वजनिक कमांड का उपयोग न करें। एक ही कमांड प्रोजेक्ट का ढाँचा तैयार करता है और इंस्टॉल करता है; यह प्रदाता खाते नहीं बनाता और न ही क्रेडेंशियल कॉन्फ़िगर करता है।

## प्रमाणीकरण चुनें [#choose-authentication]

डेटाबेस चुनने के बाद, **Better Auth** (डिफ़ॉल्ट) या **Clerk** चुनें। Better Auth सत्यापन और रीसेट ईमेल के लिए Resend का उपयोग करता है। Clerk अपने प्रबंधित कंपोनेंट और ईमेल डिलीवरी का उपयोग करता है; उस प्रोजेक्ट में Better Auth और Resend शामिल नहीं होते।

CI के लिए, स्थानीय इनिशियलाइज़र कमांड में `--auth clerk` या `--auth better-auth` जोड़ें। इनमें से किसी भी विकल्प को `--database neon` या `--database supabase` के साथ उपयोग करें। `--list-tools` फ़ाइलें बनाए बिना समर्थित विकल्पों की सूची दिखाता है। लाइव प्रमाणीकरण का परीक्षण करने से पहले जनरेट की गई `AUTHENTICATION.md` के निर्देशों का पालन करें। ये विकल्प स्वतंत्र प्रोजेक्ट बनाते हैं; ये मौजूदा उपयोगकर्ताओं को सेवाओं के बीच माइग्रेट नहीं करते।
