## उदाहरण संसाधन [#the-example-resource]

निजी नोट्स बनाने, पढ़ने, अपडेट करने और हटाने की संपूर्ण कार्यप्रणाली दर्शाते हैं। सर्वर पर इनपुट के लिए सख्त Zod स्कीमा का उपयोग किया जाता है। अज्ञात फ़ील्ड और अमान्य मान अस्वीकार कर दिए जाते हैं।

हर क्वेरी का दायरा प्रमाणित उपयोगकर्ता तक सीमित होता है। अपडेट और हटाने की कार्रवाइयों में SQL की शर्त में नोट की आईडी और स्वामी की आईडी शामिल होती हैं। दूसरे उपयोगकर्ताओं के रिकॉर्ड और अनुपस्थित रिकॉर्ड, दोनों के लिए एक ही नहीं-मिला प्रतिक्रिया लौटाई जाती है।

## डेटाबेस की सुरक्षा [#database-protection]

सभी आधारभूत तालिकाओं में क्लाइंट नीतियों के बिना पंक्ति-स्तरीय सुरक्षा सक्षम होती है। BYPASSRLS के बिना गैर-स्वामी भूमिकाओं को सीधे पहुँच की अनुमति नहीं होती। Supabase के सार्वजनिक स्कीमा और Data API का उपयोग करते समय यह महत्वपूर्ण है।

एप्लिकेशन डेटाबेस के स्वामी के रूप में कनेक्ट होता है, इसलिए सर्वर पर स्वामित्व की जाँच अनिवार्य रहती है। उपयोग में न आने वाले Supabase Data API को अक्षम करें और सभी कनेक्शन स्ट्रिंग निजी रखें।

## उदाहरण हटाएँ [#remove-the-example]

नोट्स का UI, `apps/app/src/lib/notes.ts` और `apps/app/src/app/api/notes` हटाएँ। डैशबोर्ड व्यू और सेटिंग्स में सशुल्क निर्यात के लिंक की जगह अपने उत्पाद की कार्यक्षमता जोड़ें।

`packages/database/src/schema.ts` से `note` तालिका हटाएँ, फिर एक नया माइग्रेशन जनरेट करें और उसकी समीक्षा करें:

```sh
npm run db:generate
npm run db:migrate
```

किसी मौजूदा प्रोजेक्ट पर पहले से लागू माइग्रेशन को दोबारा न लिखें। हटाने वाला माइग्रेशन लागू करने से पहले डेटा हानि की समीक्षा करें। अपने वास्तविक संसाधनों के लिए स्वामित्व के परीक्षण बनाए रखें और उनका विस्तार करें।
